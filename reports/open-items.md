## O-3. 本日追加したプラグイン 3 つの実機確認

**目的**: ロジックは単体で検証済みだが、admin から実際に使ったときの挙動を確認していない。

**手順**: dev サーバーを起動し、ブラウザで操作する。

```sh
cd cms && node ./node_modules/astro/bin/astro.mjs dev stop; pnpm dev
```

| 対象 | 操作 | 期待 |
|---|---|---|
| `portable-text-policy` | `articles` の本文にコードブロックを入れて保存 | `"Body" contains a code block.` |
| | テーブル / HTMLを挿入 / 引用 / インラインコード | それぞれ対応するメッセージ |
| | 見出し → h1 | `"Body" contains a level-1 heading.` |
| | h2〜h4・太字・斜体・リンク・箇条書き・画像 | 保存できる |
| `image-dimensions` | `casts` の `avatar` に 3840×2160 以外の画像 | `"Avatar" must be exactly 3840x2160px. "<名前>" is <W>x<H>px.` |
| | `avatar` を触らず `name` だけ編集 | 保存できる（未変更フィールドを再検査しない） |
| `webp-only` | Tools → Convert images に PNG を投入 | WebP としてライブラリに入り、表に変換前後のサイズが出る |
| | メディアページから PNG を直接アップロード | 拒否され、変換ページへ誘導するメッセージが出る |
| | 4K の実物で変換 | 完了する。所要時間とファイルサイズを記録（F-24 の実測値を置き換える） |

**前提とブロッカー**

- `.env` に `EMDASH_SITE_URL` が必要（設定済み）
- `su` でログインする。Discord の Editor アカウントでも同じ結果になるはずだが、**Editor 目線での確認は別途価値がある**（無効化した 8 機能の API が 403 になり、サイドバーから消えていること）
- 下線・取り消し線は現在拒否される（O-5 の判断待ち）。テスト中に意図しない拒否に見える

**これで埋まるもの**: 本日の実装が実際に効くことの確認。要件番号としては 5-1（権限範囲）と 1-6（`options` がプラグインから読めること）に跨る。

## O-4. 実 Discord での 2-4 と 2-6

**目的**: モックでのみ合格している 2 項目を実物で確認する。2-6 は README が挙げる最後の未確認事項（Bot の特権 Intent）も解消する。

**手順**

**2-4（権限モデル）**

1. テスト用 Discord サーバーに、一般ロールのアカウントとリーダーロールのアカウントを用意する
2. 一般ロールでログインし、他メンバーの記事を編集（200 を期待）、削除（403 を期待）
3. リーダーロールでログインし、削除（200 を期待）
4. UI ではなく API 直叩きでも同じ結果になることを確認（要件が「サーバー側でも同じ結果」を求めている）

**2-6（セッション無効化）**

1. `.env` に `DISCORD_BOT_TOKEN` を設定し、Bot をテスト用サーバーへ招待する
2. `DISCORD_REVALIDATE_SECONDS` を短く（例 30）して再起動する
3. ログイン中に Discord 側でロールを外す、またはサーバーから抜ける
4. 次の再確認で拒否されることを確認する
5. **Bot で `GET /guilds/{guild}/members/{user}` を呼ぶときに特権 Intent が要るか**を確認する（README の未確認事項）

**前提とブロッカー**

- テストアカウントが 2 つ以上必要（ロール違い）。ロールを持たないアカウントもあると 2-2 の確認を兼ねられる
- Bot の作成と招待が必要（2-6 のみ）
- 2-6 は待ち時間が発生する

**これで埋まるもの**: 2-4・2-6 を実物で裏付ける。`providers/discord/README.md` の未確認事項が全て解消する。

## O-8. ツールバーからの不要項目の非表示

**目的**: `portable-text-policy` は保存時に拒否するが、ツールバーからは消えない。編集者は使えてしまい、保存時に止まる。

**手順**: 見出しドロップダウンを開いた状態の DOM が必要（h1 / h5 / h6 を個別に隠すため）。それ以外のボタンは `aria-label` を足場にできるが、日本語と英語が混在しており**ロケールに結合する**。

**前提とブロッカー**

- DOM の提供が必要
- TipTap のキーボードショートカットと Markdown 入力規則（` ``` `、`# `）は CSS では塞げない。**拒否が本体で、非表示は補助**という関係は変わらない
- CSS はページ全体に注入されるため、フィールドごとに違う方針は適用できない（現在 `portableText` は `articles.body` の 1 つだけなので問題にならない）

**これで埋まるもの**: 編集者の体験。要件番号には紐づかない。

## 着手順の提案

| 順 | 項目 | 理由 |
|---|---|---|
| 1 | O-1 | 前提が揃っており、項目 2 と 5 の鮮度が一度に埋まる |
| 2 | O-5 → O-3 | O-5 を決めてから O-3 を実施すると、テストが素直になる |

| 5 | O-2 | スクリプト改修。記録の仕方の判断が要る |
